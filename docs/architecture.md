# 系统架构

## 分层

```
┌──────────────────────────────────────────────────────┐
│ 前端  React 19 · TypeScript · Zustand · TanStack Query │
└───────────────────────┬──────────────────────────────┘
                        │ REST + SSE（长任务进度流）
┌───────────────────────▼──────────────────────────────┐
│ API 层  FastAPI（async）                               │
├──────────────────────────────────────────────────────┤
│ 编排层                                                 │
│   · Autopilot 主循环 —— 目标驱动纯 ReAct               │
│   · 写作子流水线 —— 构思 → 草稿 → 审核 → 修订 → 定稿    │
│   · 指令编排 —— 对话式操作既有数据                      │
├──────────────────────────────────────────────────────┤
│ 能力层                                                 │
│   · LLM 路由 —— 按任务分配模型档位，可被用户级配置覆盖   │
│   · 上下文装配 —— 记忆检索 · 预算裁剪 · 三段式注入       │
│   · 一致性审校 —— 七类问题扫描                          │
│   · AI 味检测 —— 确定性词表/正则，无 LLM 调用            │
├──────────────────────────────────────────────────────┤
│ 数据层  PostgreSQL · SQLAlchemy 2.0 (async) · Alembic  │
└──────────────────────────────────────────────────────┘
```

## Agent 主循环

```
用户简报（需求 / 限制 / 目标）
      │
      ▼
task_intake ──► 结构化意图：deliverables 多选（封闭词表）
      │
      ▼
确定性派生授权范围（并集 + 依赖闭包，fail-closed）
      │
      ▼
┌───────────────── ReAct 循环 ─────────────────┐
│  读【进度摘要】→ 选工具 → 执行 → 更新进度      │
│      │                                       │
│      ├── 需要人审？ → 闸门① 规划确认（挂起）  │
│      ├── 需要人选？ → 闸门② 选项确认（挂起）  │
│      └── 工具不在白名单 → 直接拒绝             │
└──────────────────────┬───────────────────────┘
                       ▼
              验收 → 修订闭环 → 收尾
```

**为什么不用阶段状态机**：早期版本用过 7 阶段状态机，后来整体移除。
固定阶段推进靠模型自觉、阶段验收靠自由裁量，反而脆弱——模型为了"通过阶段门"会空转。
该强约束的地方是**权限**（白名单），不是**流程顺序**（引导即可）。

详见 [`../examples/agent-loop/`](../examples/agent-loop/) 的骨架实现。

## 写作子流水线

单章生成不是一次调用，而是一条带回路的小流水线：

```
章节细纲 + 注入上下文
      │
      ▼
  分拍构思（beat）
      │
      ▼
  逐拍草稿  ──►  审核（问题定位） ──►  修订
      │                                  │
      └──────────── 未过审则回到修订 ◄────┘
      │
      ▼
  定稿 → AI 味收口（确定性规则扫一遍，命中则定点改写）
      │
      ▼
  记忆提取 → 现状更新 → 一致性扫描
```

两个设计细节值得注意：

- **AI 味检测不走 LLM**。词表 + 正则的确定性检测，成本接近零、结果可复现，
  且能给出"命中哪个词、在哪一句"的可操作信息。LLM 判断"读起来像不像 AI 写的"既慢又不稳定。
- **每章定稿后立即同步记忆与现状**，不留批次。否则中途中断会丢已写章节的上下文，
  续写时前后对不上。

## 可观测性

长任务（一次自主创作可能跑几十分钟、几十次 LLM 调用）最难的是**失败后定位**。

- **SSE 事件流**：前端实时看到 Agent 在做什么，事件可回放（刷新页面看到的状态与离开前一致）
- **进度摘要由代码计算**，不是模型自述——避免"模型说自己完成了 80%"这类不可信状态
- **看门狗**：独立线程监测事件循环，卡住超时打印所有线程的 Python 栈（直接指出阻塞行）。
  这在 asyncio 单线程服务里是必需品——一个同步调用就能把整个服务冻住，
  而外部只能看到"页面全白"，看不出原因。
